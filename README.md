# claude-ops

Claude Code 세션 여러 개를 한 리눅스 기계에서 상시 돌리고, 텔레그램으로 조작하고,
멈추거나 한도에 걸렸을 때 알아서 되살아나게 하는 운영 도구 모음이다.

세션 하나가 systemd user 서비스 하나다. 각 세션은 자기 텔레그램 봇에 붙어 있어서,
바깥에서 그 봇에 말을 걸면 그 세션이 답한다. 그 위에 감시 타이머와 훅이 얹혀 있어
세션이 멈추면 다시 띄우고, 한도에 걸리면 풀리는 시점에 다시 깨운다.

## 기본 구성 — 상시 데몬, 대화는 텔레그램으로만

이 저장소가 전제하는 쓰는 방식은 하나다. 모든 것이 systemd user 데몬으로 상시 돌고, 사람은
텔레그램으로만 대화한다. 터미널은 처음 세울 때와 사람만 할 수 있는 몇 자리(토큰 넣기,
전화번호 인증, 짝짓기 승인)에만 쓴다. 데몬이라 재부팅해도 세션·감시·봇이 저절로 다시
켜진다. 텔레그램 쪽은 세 가지가 다 있어야 기본 구성이다 — 하나라도 빠지면 그 몫(대화,
감시와 제어, 세션 협업)을 터미널로 메워야 한다.

- 세션 봇 — 세션 하나에 봇 하나. 그 봇에 말을 걸면 그 세션이 일하고 답한다.
- 통제 봇(control bot) — 세션과 따로 사는 관리 창구. 세션이 멈추거나 한도에 걸려 답을 못
  할 때도 살아 있어서 상태 보기, 세션 재시작, 계정 바꾸기·재로그인, 넛지 켜고 끄기를
  버튼으로 한다. 여러 감시와 제어가 이 창구로 모인다.
- 유저봇(userbot) — 자기 텔레그램 계정으로 로그인한 발신기. 봇은 다른 봇에게 말을 못
  걸기 때문에, 세션이 다른 세션에 지시를 넣거나 세션 밖에서 돈 긴 작업의 결과가 띄운
  세션으로 돌아오는 길이 이것이다. 토론 도구·세션 밖 긴 작업 같은 추가 기능과 세션 협업이
  이걸 전제로 돈다.

만드는 법은 SETUP.md 에 있다 — 세션 봇 3-a~3-d, 통제 봇 3-e, 유저봇 6절, 데몬 켜기 7절.

## 받았으면 이 순서로

가장 쉬운 길: 이 저장소 폴더에서 Claude Code 를 열고 "README 읽고 이 기계에 세워 줘" 한
마디만 한다. 아래 안내가 에이전트를 필요한 문서로 차례로 데려간다.

> 에이전트에게: 사람이 이 저장소를 세워 달라고 했으면 지금 `AGENT-SETUP.md` 를 열어 그
> 순서대로 끝까지 한다. 봇 토큰·텔레그램 사용자 번호·`sudo` 명령처럼 사람이 해야 하는
> 자리에서는 멈추고 무엇을 하라고 알려 준다. 다 세운 뒤에는 아래 2·3번을 사람과 같이 한다.

1. 세우기 — 위처럼 에이전트에게 맡기거나, 손으로 SETUP.md 를 위에서 아래로 한 번 따라간다.
   봇 만들기부터 첫 대화까지다.
2. 확인 — `claude-ops-doctor` 를 돌려 빠진 것이 없는지 본다.
3. 써 보기 — EXAMPLES.md 의 여섯 가지(설치 확인, 세션 하나 더 띄우기, 멈춘 세션 되살리기,
   기록 보관 후 새로 시작, 토큰이 어디로 가는지 재기, 두 번째 기계 맞추기)를 차례로 해 본다.
4. 규칙 고치기 — 세션이 따르는 작업 규칙은 `claude/CLAUDE.md` 다. 자기 방식에 맞게 고치고
   `./install.sh` 를 다시 돌린다.

## 무엇이 들어 있나

- `systemd/user/` — 세션 유닛과 감시 타이머. 세션 유닛의 본보기는 `claude-dotfiles.service`
  이고, 새 세션 유닛은 `claude-service-template` 이 폴더 경로만 받아 만들어 준다.
- `bin/` — 운영 명령. 세션 통제(`claude-sessions`, `claude-soft-restart`, 통제 봇 `claude-control-bot`), 감시
  (`claude-session-healthcheck`, `claude-stall-guard`, `claude-watchdog`,
  `claude-api-5xx-watcher`), 한도 관측과 재개(`claude-quota-observe`,
  `rate-limit-recovery`), 세션끼리 메시지를 넣는 통로(`claude-userbot-send`),
  외부 모델 세 개를 붙여 토론시키는 `ai-debate`.
- `claude/hooks/` — Claude Code 훅. 긴 프롬프트 차단, 한도 차단과 큐 적재,
  장시간 작업을 세션 밖으로 내보내는 가드, 산출물 경로 가드 따위.
- `claude/CLAUDE.md`, `claude/RATIONALE.md` — 모든 세션이 공유하는 작업 규칙과
  그 규칙이 생긴 근거. 규칙 본문의 `[R##]` 이 근거 파일의 같은 번호를 가리킨다.
- `userbot/` — 세션끼리 메시지를 넣는 통로의 설정 본보기. 기본 구성의 하나다(SETUP.md 6절).
- `lib/` — 여러 감시기가 같은 판단을 하도록 규칙을 한 곳에 모은 것.
- `tests/` — 위의 것들이 갈라지지 않는지 보는 검사.
- `install.sh` — 위를 제자리에 심는다.

## 기본 테스트 명령

저장소 기본 테스트 명령의 정본은 이 절이다. 다른 곳에 같은 명령을 적지 않는다.

저장소 루트에서 다음 한 줄을 돌린다. 대상은 `tests/` 밑의 파이썬 파일 전부다.

```
bash -c 'r=0; for f in tests/*.py; do python3 "$f" || r=1; done; exit "$r"'
```

각 파일은 자기 안에서 통과·실패를 세고 마지막에 종료코드를 낸다. 위 반복문은
하나라도 실패하면 1로 끝난다. 러너·Makefile·설정 파일은 두지 않는다 — 파일을 늘리는
대신 셸 한 줄로 끝나는 일이다.

기계마다 달라지는 자리는 검사 안에서 건너뛰기를 찍고 그 사유를 출력한다.

## 전제

- 리눅스. `systemctl --user` 가 도는 환경이어야 한다(Ubuntu 20.04 이상에서 쓰고 있다).
- 파이썬 3.8 이상. 표준 라이브러리만 쓴다.
- Claude Code CLI. 텔레그램 연결에는 bun 이, 토론 도구에는 외부 모델 CLI 가 더 필요하다.

## 안 들어 있는 것

토큰과 방 번호는 이 저장소가 다루지 않는다. 각자 자기 기계에 직접 넣는다 — 자리는
SETUP.md 에 적어 뒀다. 특정 회사·조직에 묶인 자동화와 개인 일정에 묶인 보고 도구는
빼고 옮겼다.

규칙 문서에 나오는 `session-a`·`proj-b` 같은 이름은 실제로 돌던 세션을 가리키던 자리다.
사고 경위가 문장의 근거라 지우지 않고 일반 이름으로 옮겼다.
