# AI 합의 토론 (단일 진입점)

## 핵심
- 모든 협업/토론 트리거는 ai-debate CLI 한 가지 경로로 통일.
- 풀 = [codex, gemini, claude]. 라운드마다 풀의 각 agent 를 역할 수만큼 호출 (기본 역할 debater+critic → 3 agent × 2 역할 = 6콜/라운드).
- claude 는 격리 HOME(~/.claude-iso)으로 호출 → 부모 세션 telegram MCP / .claude.json 충돌 회피 (그래서 풀에 포함 가능).
- 일부 provider(예: gemini 429, codex 장애)가 죽어도 나머지로 debater+critic 확보됨.
- JSON 표준 출력. 라운드 간 이전 출력을 컨텍스트로 전달. 합의되면 조기 종료, 안 되면 max_rounds 까지 반복 (기본 2, --deep 시 5).
- 합의 조건: critic 전부 should_proceed=true + debater position 수렴.
- 최종은 codex arbiter가 final_decision/action_steps/verification_plan/dissent로 통일 정리.
- 성공 콜 / 예정 콜 < 2/3 이면 arbiter 건너뛰고 실패 종료.
- 산출물 ~/claude-work/ai-debate/run-<ts>/ 저장.

## 호출 규칙
- 부르는 명령은 `ai-debate-detach` 하나다. `ai-debate` 를 세션에서 직접 부르면 PreToolUse 훅 bg-longjob-guard 가 막는다(foreground·background 무관).
  `cat brief.md | ai-debate-detach [--slug <이름>] "<질문>" [ai-debate 옵션...]` — 옵션은 ai-debate 것을 그대로 넘긴다.
- foreground 로 부른다(즉시 반환한다). run_in_background 로 띄우면 제출 자체가 세션 재시작에 죽어 토론이 시작조차 안 될 수 있어 훅이 막는다.
- 그 턴에는 결과가 없다. 토론은 세션 밖 systemd 유닛에서 돌고, 끝나면 1,800자 이하 요약과 run_dir 경로가 이 세션으로 주입된다. 요약만 보고 판단하지 말고 run_dir 원문을 읽는다. 실패하면 detach 가 알리고, 주입 자체가 실패하면 rc 4 로 시끄럽게 죽는다(캡슐은 작업폴더 capsule.txt 에 남는다).
- 제출 직전 한 줄 사전 고지 필수 ("토론을 세션 밖에서 시작한다, 결과는 나중에 들어온다").
- 작업폴더는 `<세션 cwd>/state/ai-debate/<시각>-<slug>/` (brief.md·args.json·run.log·capsule.txt).
- 기본 2라운드 + arbiter. --deep 5라운드면 더 걸린다. 이제 Bash 도구 상한 600초와 무관하다.
- task arg는 짧게. 중간 크기 컨텍스트는 stdin 으로, 큰 문서는 붙여넣지 말고 경로로(아래 "브리프 작성" 참조).
- 프로젝트 메모리는 기본 OFF. 토론 품질 보호. 필요 시 `--with-memory`.
- 라운드: 기본 2. 가벼우면 `--max-rounds 1`, 깊게는 `--deep`(5라운드).
- 동적 역할: `--auto-roles` (planner LLM 이 task 보고 역할 자동선정, critic 자동추가), `--max-roles N`(기본 4).
  명시는 `--roles debater,...`. 예산 가드 `--max-total-calls`(기본 24, 초과 시 시작 전 중단). `--dry-run` 으로 예상 콜수만.
- 캐시: 같은 task 24h 재호출 시 캐시. 우회 `--no-cache` 또는 `--seed`.

## 브리프 작성 — 큰 문서는 붙여넣지 말고 경로로 (2026-08-17 사용자 지시, session-p 세션 실측)

원고·응답서·소스처럼 큰 문서를 검토시킬 때는 본문을 프롬프트에 넣지 않는다. 절대경로 목록만
넘기고 각 debater 가 직접 열어 읽게 한다.

붙여넣기가 실패하는 방식은 셋이고, 경로 방식은 셋을 동시에 없앤다.
- gemini 는 argv 로만 받는다(agy 는 stdin 을 안 읽는다). 약 100KB 를 넘으면 그 agent 가 죽고,
  성공 콜이 2/3 밑으로 떨어지면 arbiter 에 못 가서 토론이 통째로 날아간다.
  2026-08-16 run-20260816T093628Z 가 127KB 로 실제로 그렇게 실패했다.
- 크기를 맞추려고 참고문헌·표·중복을 잘라내면 debater 가 잘린 문서를 근거로 판단한다.
  "이미 반영된 것을 미반영으로 오판" 하는 실패가 반복됐다.
- pdftotext 로 평문화하면 표 구조와 LaTeX 소스가 사라져 수치 대조 자체가 불가능해진다.

브리프에 반드시 넣을 네 가지.
1. "본문을 붙여넣지 않았다. 각자 파일을 열어 전문을 읽어라" 를 명시.
2. 절대경로 목록 + 각 파일이 무엇인지 한 줄 설명.
3. 하드 제약 목록(페이지 수·마감·바꾸면 안 되는 것 등).
4. "지적하기 전에 소스에서 실제로 grep 해서 확인해라" — 이 문장이 오판을 줄인다.

검토 대상이 많으면 필수 자료와 참고 자료를 나눠 적는다. 표지 두 개를 줄 안에 쓰면 그 줄부터
역할이 바뀐다.

```
검토 대상: /경로/원고.md
[참고 자료]
/경로/지난회차보고서/
[필수 자료]
/경로/응답서.md
```

나눠 적으면 합본(BRIEF-FULLTEXT.txt)에는 필수만 들어간다. 참고 자료는 사본 트리에 그대로
있어서 참여자가 필요할 때 열 수 있고, 무엇이 왜 들어가고 빠졌는지는 사본 뿌리의
BRIEF-MANIFEST.txt 에 파일 단위로 남는다. 표지를 안 쓰면 전부 필수로 보고 예전과 똑같이 돈다.

나누는 이유는 합본 상한이다(1,500,000바이트). 홈의 논문 검토 회차가 그 상한에 부딪혀 검토
대상 절반이 합본 밖에 남았고(들어간 63개·빠진 73개), 그러면 "합본 하나를 한 번에 읽어라" 가
성립하지 않아 참여자가 나머지를 개별로 연다 — 나눠 읽는 횟수가 값을 정하므로 그게 제일 비싸다.
상한을 올리는 것은 답이 아니다. 한 번에 안 읽히는 것은 그대로다.

실패 계약(2026-08-17 실측 후 구현으로 강제). 브리프에 절대경로가 있으면 ai-debate 가 모든
agent 프롬프트에 "직접 열어 읽어라, 요약본·오래된 사본으로 대체하지 마라, 못 읽었으면 어느
경로를 못 읽었는지 밝히고 그 판단을 보류해라, 수치는 출처 파일과 함께 적어라" 를 자동으로
붙인다. 브리프에 따로 안 써도 된다.

원본은 agent 에게 안 넘어간다(2026-08-17 peer 실측 + run-20260817T135425Z 결론, 구현 완료).
`--add-dir` 는 읽기 전용이 아니다 — agy 는 열어준 디렉토리의 파일을 실제로 고쳤다(md5 변경 확인).
codex 헤더는 sandbox: read-only 로 뜨지만 bubblewrap user namespace 경고가 있어 실제 격리는
미확인이라 셋 다 쓸 수 있다고 가정한다. 그래서 ai-debate 가 호출마다 브리프 경로의 사본을
만들고 프롬프트의 경로를 사본 경로로 치환한다. 원본 절대경로는 어떤 agent
프롬프트에도 안 남는다. 사본을 호출별로 나누는 이유는 오염이다 — 공유 사본이면 한 debater 가
고친 것을 다음 debater 가 근거로 읽고, 끝난 뒤 diff 로는 누가 고쳤는지 못 가린다.
보조 방어 둘도 자동이다: 프롬프트에 "이 경로 밖 접근·수정 금지"(사본 안 문서가 원본 경로를
인용하고 있으면 따라갈 수 있다), 그리고 런 끝에 원본 md5 재검증(변경 감지 시 stderr +
run_dir/origin-integrity.txt). 브리프 쓰는 쪽이 신경 쓸 건 없다 — 실제 경로를 그대로 적으면 된다.
심링크·하드링크는 대안이 아니다(따라가면 원본, 하드링크는 같은 inode). `cp --reflink` 도 이
머신에선 루트가 ext4 라 거절된다.

폴더째 넘겨도 된다("이 저장소 코드를 다 봐라"). 사본 상한은 파일 6000개 / 총 512MB /
파일당 8MB 이고, dotfiles 저장소 전체가 257파일 2MB 0.04초였다. 상한에 걸리면 조용히 자르지
않는다 — 빠진 파일 수·목록을 프롬프트에 붙이고 "전수 판단 하지 말고 전수 확인 불가라고
밝혀라"를 강제하며 stderr 로도 경고한다. 사본은 런이 끝나면 지운다(무엇을 넘겼는지는
`*.prompt.txt` 에 남는다). 보존하려면 `AI_DEBATE_KEEP_SNAPSHOT=1`.

사본은 읽기 전용이 아니라 그 호출 전용 작업본이다(2026-08-18 사용자 지시 "능력이 더 중요하다").
파일 모드는 644 이고 프롬프트도 "이 트리 안에서는 고치고 실행해도 된다, 밖은 열지 마라" 로
바뀌었다 — 고쳐보고 확인한 근거가 읽기만 한 근거보다 낫고, 사본이라 원본에 영향이 0 이다.
원본 방어는 파일 모드가 아니라 "원본 경로를 아예 안 준다" 쪽이다.

숨김 파일도 이제 사본에 들어간다. 빼는 건 이름 부정목록뿐이다 — 자격증명(`.ssh` `.env*`
`.aws` `.pgpass` `id_*` `*credential*` `*.pem` `*.tfvars` 등)과 파생물·노이즈(`.git`
`node_modules` `__pycache__` `.venv`). `.config`·`.local`·`.cache` 는 홈 바로 밑일 때만
빼고 저장소 안에 있는 건 남긴다.
그래서 `.github/workflows`·`.gitignore`·`.eslintrc` 는 그대로 보인다(옛 규칙은
`.` 로 시작하면 전부 뺐고, 그 탓에 "설정이 없다" 는 틀린 근거가 나왔다). `.git` 을 빼는
대신 디렉토리 사본 루트에 `GIT-CONTEXT.txt` 를 만들어 최근 커밋 30·현재 상태·미커밋 변경
요약을 넣는다 — 이력은 주고 객체 저장소는 복제하지 않는다.

읽었는지는 자기보고 말고 흔적도 같이 본다. 런 요약의 "읽기 흔적(사본 atime, 하한)" 줄이
agent 별로 사본 파일 중 열린 흔적이 남은 수를 보여준다(판정: atime > mtime, 갓 복사한
파일은 둘이 같다). 이건 하한이지 증명이 아니다 — 흔적이 있으면 읽은 것이고, 0 은 모른다는
뜻이다. 실제로 codex 는 읽기전용 바인드 마운트를 통해 열어서 atime 을 안 남긴다
(run-20260818T011817Z: codex 0/12 로 찍혔지만 카나리아 두 개를 정확히 인용했다).
noatime 마운트면 아예 "측정 불가" 로 낸다. agent 가 만들거나 고친 파일은 분모에서 뺀다.

실패한 콜은 1회 자동 재시도한다(JSON parse 실패·비정상 종료만). 한도(429)와 timeout 은
재시도 안 한다 — 한도는 같은 벽이고 timeout 재시도는 남은 시간 예산을 먹어 다른 agent 까지
죽인다. 재시도분 산출물은 `<label>.retry.*` 로 남는다.

누가 실제로 읽는지(2026-08-17 canary 실측, run-20260817T093541Z).
- claude: 읽는다. ai-debate 가 브리프에 적힌 경로의 디렉토리를 `--add-dir` 로 열어준다.
  cwd 는 /tmp 그대로고, 숨김 디렉토리(.ssh·.claude 등)는 열지 않는다.
- gemini: 읽는다(2026-08-17 늦게 고침). agy 도 `--add-dir` 를 받고, 그것만으로 열린다 —
  위험한 플래그는 필요 없다. 그 전까지 "gemini 는 못 읽는다" 고 알고 있었는데 틀린 진단이었다:
  2026-07-22 에 도구 호출이 권한거부로 죽자 no-tools 가드를 붙였고, 그게 원인(워크스페이스
  미개방)이 아니라 증상을 막은 것이라 이후로 계속 못 읽는 상태로 굳어 있었다. 지금은 경로가
  있는 브리프면 gemini 에도 --add-dir 를 넘기고 no-tools 문구를 뺀다. 경로가 없는 일반 토론은
  그대로 막는다(열어줄 대상도 없는데 탐색만 늘면 손해).
- codex: 미확인. 실측 당시 사용 한도 소진이라 호출 자체가 안 됐다.

문서 대조형 과제는 좁혀서 던져라. 파일을 실제로 읽기 시작하면 한 콜이 600초 상한을 넘긴다
(2026-08-17 run-20260817T094002Z: claude 2콜이 각 600초로 죽어 의견 0건, 성공 사례도 552초로
한계 근접이었다). 상한은 못 올린다 — Bash 도구 자체가 600초라 올려봐야 호출하는 쪽이 먼저
죽는다. 대신 프롬프트에 시간 예산을 자동으로 박아 부분 결론이라도 내게 했고, 브리프 쪽에서는
대상 파일 4종 이하 + 재검증 금지 항목 명시 + `--max-rounds 1` 로 좁히는 게 실제로 통했다.

이 규약은 원리가 아니라 구현에 달렸다는 걸 잊지 마라. 2026-08-17 이전에는 claude 도 못 읽어서,
한 debater 는 판단 보류만 냈고 다른 하나는 /tmp 의 stale 사본으로 검증해 존재하지 않는 불일치를
지적했다(avia AugPF-LW 를 7.606/34.113 로 인용, 커밋본은 7.416/31.027). 규약을 바꿀 때는
canary 파일 1개로 실제 읽히는지 먼저 재라.

## 출력 형식 (사용자 응답)
- 라운드별 한 줄 요약 (debater positions / critic should_proceed 표시)
- 마지막에 ARBITER 블록: FINAL + rationale + action_steps + verification_plan + dissent
- 토큰 절약 위해 모든 debater/critic 원문은 dump 안 함. run_dir 경로만 안내.

## 실패 처리
- gemini 429/parse 실패는 자연스럽게 무시 (codex/claude 로 충분). 사용자 알림 불필요.
- 성공 콜 / 예정 콜 < 2/3 이면 arbiter 건너뛰고 실패 종료 (라운드 결과는 dump).
- arbiter(codex) 실패면 그 사실만 알리고 라운드 결과 dump.

## 코드 리뷰 변형
"AI한테 코드 리뷰" / "AI한테 리뷰 받아" 트리거:
- /code-review (Claude 멀티에이전트) 실행과 병행해서 `cat file | ai-debate-detach "리뷰: <파일> 의 문제점·개선안"` 호출.
- 통합: 공통 지적(고신뢰) / 단일 지적(검토) / arbiter 권고안.
