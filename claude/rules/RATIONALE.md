# 규칙 근거 (RATIONALE)

전역 CLAUDE.md 본문의 각 규칙에 붙은 번호가 이 파일의 앵커다. 번호는 한 번 정하면 안 바꾼다 —
새 규칙은 뒤에 잇고, 규칙이 없어져도 번호는 재사용하지 않는다.

이 파일은 세션 시작 때 자동으로 안 실린다. 다음 넷 중 하나일 때 해당 번호를 찾아 읽는다.

- 그 규칙의 예외를 만들려 할 때
- 그 규칙을 바꾸거나 지우려 할 때
- 그 규칙과 관련된 사고를 진단할 때
- 본문 문장의 뜻이 갈릴 때

아래 항목은 축약 전 본문 원문이다. 본문에는 명령·범위·조건·예외·짧은 실패 기제·안전한 대안·
복구 동작만 남아 있고, 여기 남은 원문이 무엇이 빠졌는지를 대조하는 기준이다.

### R03

- 운영자가 읽는 글(텔레그램 답장·보고서·판정문)에는 임의로 만든 축약(`lk`·`gt` 같은 것)·영어 약자·원문을 마음대로 옮긴 말을 쓰지 않는다. 처음 나오는 용어는 풀어 쓰고 그게 무엇을 재는 값인지 한 줄 붙인다. 세션끼리 주고받는 통보도 운영자 화면에 그대로 뜨므로 같이 적용한다. (2026-08-23 운영자 지시 — session-b 이 session-a·session-n 를 `lk`·`gt` 로 줄이고 "게이트폭" 이라는 말을 만들어 써서 운영자가 두 번 되물었다. 원문: "앞으로 줄임말 쓰지마 항상 내가 이해할수있는 표현으로 사용해 맘대로 줄이지도말고 번역하지도 말고 사람이 이해할수있는 직관적이고 직설적인표현을 써".)

## 시각 표기 (KST)

### R07

progress.md / history.md 의 updated/timestamp 필드는 반드시 시스템 KST 시각으로 쓴다. UTC 사용 금지. 시각 가져올 때 `date '+%Y-%m-%d %H:%M KST'` 또는 Python `datetime.now()` (시스템 timezone Asia/Seoul) 사용. `date -u` 나 `datetime.utcnow()` 결과를 KST 라벨로 쓰면 9시간 어긋남. (2026-05-21 session-k 세션 02:13 KST 라벨 사고 후 추가.)

## 도구 규칙

### R20

- 사용자에게 보여주려고 만드는 설명 문서(리포트·정리·비교·조사결과·가이드)는 기본 HTML 로 만든다. md 로 만들라는 명시가 있을 때만 md. 텔레그램에서 md 원문은 읽기 나쁘고 HTML 은 열면 바로 읽힌다(2026-07-31 사용자 요청). 대상이 아닌 것: progress.md·history.md·CLAUDE.md·README 같은 기계·규약용 파일, 코드 주석, 채팅 답변 자체.

### R22

- 민감 경로 — 세션 산출물(임시 스크립트·로그·메모·체크포인트)을 `.claude` 밑에 만들지 않는다. Claude Code 는 Write/Edit 대상 경로에 특정 세그먼트가 들어 있으면 `permissions.allow` 와 무관하게 매번 사람 승인을 묻는다(CLI 2.1.220 바이너리에서 직접 확인). 대상: `.git .vscode .idea .claude .husky .cargo .devcontainer .yarn .mvn`, `.config/git`, 그리고 `.gitconfig .bashrc .zshrc .profile .envrc .mcp.json .claude.json .npmrc .bazelrc bunfig.toml` 같은 파일명 목록. `.claude` 밑 예외는 `skills`·`agents`·`commands`·`worktrees`·`scheduled_tasks.json` 뿐이라 `.claude/state/**` 는 전부 걸린다. 산출물은 그 세션이 일하는 디렉토리 안에 만들되 숨김폴더(`.` 로 시작하는 이름) 밑에 두지 않는다 — 기본은 `<세션 cwd>/state/<job-id>/` 다(2026-08-03 사용자 지시). 커밋할 게 아니면 그 프로젝트 `.gitignore` 에 `state/` 를 넣는다 — 숨기는 것과 추적 제외는 다른 얘기다. 승인 대기는 transcript 에 안 남아서 세션이 조용히 정지한다 — 2026-08-03 session-b 이 `.claude/state/...` 에 정상 스크립트를 Write 하려다 걸렸다. 이 판정은 훅으로도 규칙으로도 못 뚫는다(2.1.220 코드 확인): PreToolUse 가 `allow` 를 줘도 안전검사가 `ask` 를 만들어 "Hook returned allow …, but ask rule/safety check requires full permission pipeline" 로그와 함께 전체 권한 파이프라인을 다시 탄다. `deny` 만 유효하다 — 훅으로 막는 건 되고 뚫는 건 안 된다. `allow` 의 bare Write 가 무력한 것도 같은 이유고 설계된 동작이다. 그러니 경로를 바꾸는 것 말고 다른 해법은 없다.

### R23

- 위 판정을 Bash 로 우회해 쓰지 않는다. `Bash(*)` 가 allow 라 안 물어보긴 하지만, 그건 플랫폼이 세운 경계와 우리 Write|Edit 매처 훅(progress-md-path-guard·auto-verify·html-charset-inject)을 동시에 건너뛰는 것이다. 경로를 바꾸면 우회할 일 자체가 없다. 불가피한 예외는 사람 지시가 있을 때만. (2026-08-03 ai-debate run-20260803T121501Z — 옆 기계 원안의 "Bash 로 써라" 2항은 이 이유로 기각됐다.)
